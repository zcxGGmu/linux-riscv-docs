# 大模型定价与团队用量评估汇报 - PPT 大纲

适用对象：管理层 / 技术负责人 / 采购决策人
建议页数：8~10 页
建议风格：深色封面 + 浅色内容页，突出“成本、风险、建议”三条主线

## Slide 1. 封面

标题：
大模型定价、限制与研发团队月度用量评估

副标题：
围绕 GLM-5.1、Claude Opus、GPT-5 的选型与预算分析

建议呈现元素：
- 左侧主标题
- 右侧 3 个关键词标签：定价 / 限制 / 用量
- 页脚：汇报人、日期

演讲备注：
- 本次汇报目标不是做纯参数罗列，而是回答三个问题：
  1. 市面上主流模型大致怎么定价
  2. 对 20 人团队月度消耗量怎么估算
  3. 最后该怎么选型、怎么控成本

## Slide 2. 管理层最关心的结论

标题：
一页看结论

核心信息：
- 本次对比中，`Claude-opus-4.6`、`GPT-5.4` 不是厂商公开官方命名，报告分别按 `Claude Opus 4.1`、`GPT-5` 对比
- 20 人团队基线场景月消耗约 `94.60M tokens`
- 基线场景月成本估算：
  - GLM-5.1：`$143.11`
  - Claude Opus 4.1：`$2,871.00`
  - GPT-5：`$330.00`
- 成本大头主要来自：`代码开发 + Review loop`
- 推荐策略不是单模型全覆盖，而是“低成本主力 + 高质量升级模型”组合

建议版式：
- 左侧：3 条关键结论卡片
- 右侧：1 个基线成本对比柱状图

演讲备注：
- 如果只记住一件事，就是“预算的关键不在需求分析，而在开发和 Review 的高频调用”。

## Slide 5. 为什么团队用量会集中在开发与 Review

标题：
Token 消耗的主要来源在哪里

核心内容：
- 需求生成虽然单次对话长，但频次相对低
- 开发与 Review 环节：
  - 高频
  - 多轮反复
  - 要携带代码上下文、日志、diff、修改结果
- 测试验证阶段：
  - 环境排障 often 需要多轮追问
  - 测例编写会反复补充边界条件

建议图形：
- 一条研发流程链路图：
  需求生成 -> 开发 -> Review -> 测试 -> 回流修复
- 在“开发 / Review”节点画最大气泡

演讲备注：
- 研发场景下，大模型不是一次性调用，而是天然形成 loop，这就是成本放大的根源。

## Slide 9. 选型建议：不要单模型全覆盖

标题：
推荐采用“分层模型策略”

核心建议：
- 默认模型：`GPT-5` 或 `GLM-5.1`
  - 用于日常开发、常规 Review、测试辅助
- 升级模型：`Claude Opus 4.1`
  - 用于复杂架构分析
  - 高风险 PR 二次 review
  - 疑难性能问题定位
- 原因：
  - 保留高质量能力
  - 同时避免日常成本失控

建议版式：
- 左右双栏：
  - 左栏“默认流量”
  - 右栏“升级流量”
- 中间用箭头表示升级条件

演讲备注：
- 真正高性价比的策略通常不是选一个“最强模型”，而是构建“主力模型 + 专家模型”的分层体系。

---

## Slide 10. 落地建议与下一步

标题：
预算、治理与落地建议

建议列 5 条：
1. 以“基线场景 94.60M tokens/月”作为预算测算起点
2. 默认启用缓存、上下文复用、模板化 prompt
3. 对 Review loop 设置轮次阈值，避免无上限反复对话
4. 将环境排障、测例编写优先落到低成本模型
5. 对关键任务保留高端模型升级通道

页尾补一句：
建议先试运行 1 个月，基于真实调用日志再校准预算模型

演讲备注：
- 先跑试点，再按日志回填预算，是比“静态估算”更稳妥的采购方式。

## 制作建议

### 视觉风格
- 封面深色：深蓝 / 深灰
- 内容页浅色：白底或浅灰底
- 强调色建议：
  - 成本：橙红
  - 风险：深红
  - 推荐方案：绿色

### 字体建议
- 标题：36~40 pt
- 正文：16~18 pt
- 重点数字：28~36 pt

### 汇报节奏建议
- 1~3 页：交代范围、口径、结论
- 4~8 页：展示核心事实和数据
- 9~10 页：给出明确决策建议

### 一句话收尾
建议在最后一页用一句话收尾：
“建议采用低成本主力模型承接日常流量，以高质量模型承接关键复杂任务，在保证效果的同时控制团队级成本。”
