# Claw Code 哲学

> 原文来源：`https://github.com/ultraworkers/claw-code/blob/main/PHILOSOPHY.md`
> 相关 X 帖子：`https://x.com/realsigridjin/status/2039472968624185713`

## 别只盯着文件看

如果你只看这个仓库里生成出来的那些文件，那你看的就是错的层。

Python 重写版只是副产物，Rust 重写版也只是副产物。真正值得研究的，是**产出这些东西的系统**：一个基于 clawhip 的协同循环，人类负责给出方向，自主 claws 负责执行工作。

Claw Code 不只是一个代码仓库。它更像是一个公开展示：当下面这些条件同时成立时，会发生什么：

- 人类提供清晰方向；
- 多个编码代理并行协作；
- 通知路由被移出代理的上下文窗口；
- 计划、执行、审查与重试循环被自动化；
- 人类不再坐在终端前，对每一步进行微观管理。

## 人类接口其实是 Discord

这里真正重要的接口，不是 tmux、Vim、SSH，也不是终端复用器。

真正的人类接口，是一个 Discord 频道。

一个人可以用手机发一句话，然后离开、睡觉，或者去做别的事。claws 会读取指令，把它拆成任务，分配角色，编写代码，运行测试，围绕失败展开争论，进行恢复，并在工作通过后推送结果。

这就是它的哲学：**人类设定方向；claws 负责劳动。**

## 三段式系统

### 1. OmX（`oh-my-codex`）

`oh-my-codex` 提供的是工作流层。

它把简短指令转换为结构化执行：

- 计划关键字；
- 执行模式；
- 持续性的验证循环；
- 并行多代理工作流。

这一层负责把一句话，变成一个可重复执行的工作协议。

### 2. clawhip

`clawhip` 是事件与通知路由器。

它会监视：

- git 提交；
- tmux 会话；
- GitHub issue 和 PR；
- 代理生命周期事件；
- 频道消息投递。

它的职责，是把监控与投递从编码代理的上下文窗口中拿出去，让代理可以专注在实现本身，而不是状态格式化和通知路由。

### 3. OmO（`oh-my-openagent`）

`oh-my-openagent` 负责多代理协调。

计划、交接、分歧解决以及验证循环，都是在这一层跨代理发生的。

当 Architect、Executor 和 Reviewer 彼此意见不一致时，OmO 提供让这个循环走向收敛、而不是走向崩溃的结构。

## 真正的瓶颈已经变了

瓶颈已经不再是打字速度。

当代理系统可以在数小时内重建一个代码库时，稀缺资源变成了：

- 架构清晰度；
- 任务拆解能力；
- 判断力；
- 品味；
- 对什么值得构建的确信；
- 知道哪些部分可以并行化，哪些部分必须保持约束。

一个高速运转的代理团队，并不会消除思考的必要；它只会让清晰思考变得更加有价值。

## Claw Code 展示了什么

Claw Code 展示了，一个仓库可以是：

- 在公开环境中被自主构建出来；
- 由 claws / lobsters 协调，而不只是人类结对编程；
- 通过聊天界面来操作；
- 借由结构化的计划 / 执行 / 审查循环持续改进；
- 被维护为“协同层”的展示样本，而不只是输出文件的集合。

代码是证据，协同系统才是产品层面的启示。

## 仍然重要的东西

随着编码智能越来越便宜、越来越普及，真正持久的差异化因素，不再是原始代码产出能力。

仍然重要的是：

- 产品品味；
- 方向感；
- 系统设计；
- 人类信任；
- 运行稳定性；
- 对下一步该构建什么的判断。

在那样的世界里，人类的工作不是比机器打字更快；人类的工作，是决定什么值得被创造出来。

## 简短版

Claw Code 是一个“自主软件开发”的演示。

人类提供方向，claws 负责协调、构建、测试、恢复并推送结果。仓库是产物，而哲学则是产物背后的系统。
