# Linux 内核 arm64 vs riscv Kconfig 支持差异分析

## 1. 分析范围与方法
- 目标源码路径（可用实际路径）：`/home/zq/work-space/repo/patch-work/linux`
- 基线版本：`5add9af9e84fb6b952ddf7a248b4b3fa7c444907`
- 用户给定路径 `/home/zcxggmu/workspace/patch-work/linux` 在当前环境不存在，因此改用同机可用路径进行分析。

### 方法
1. 抽取 `arch/arm64/Kconfig*` 与 `arch/riscv/Kconfig*` 中全部 `config/menuconfig` 符号集合。
2. 做集合差：得到 `arm64-only` 符号。
3. 对每个 `arm64-only` 项，回溯其在 arm64 Kconfig 中的首次引入提交（commit subject/date/hash）。
4. 结合 riscv Kconfig/相关实现路径，给出三类结论：
   - `缺失`：riscv 当前没有同等能力的 Kconfig/实现入口（真实差距）
   - `部分等价`：riscv 有异名实现或能力子集
   - `不适用`：Arm 架构/厂商专属项（SoC、errata、AArch32 历史兼容等）

- 虚拟化：`PTDUMP_STAGE2_DEBUGFS` `XEN` `XEN_DOM0`

## 4. 优先级最高的缺口（建议优先补齐）
1. `ARM64_MTE` / `ARM64_AS_HAS_MTE`：RISC-V 缺少硬件内存标记路线，内存安全硬化能力差距明显。
2. `ARM64_BTI` / `ARM64_BTI_KERNEL`：缺少 Arm 级别硬件 CFI 落点保护，内核与用户态防护层级落后。
3. `ARM64_PTR_AUTH` / `ARM64_PTR_AUTH_KERNEL`：缺少指针签名链路，ROP 类防护能力缺口持续存在。
4. `UNMAP_KERNEL_AT_EL0`：缺少 arm64 同级 KPTI 控制项，用户态隔离策略可进一步强化。
5. `RANDOMIZE_MODULE_REGION_FULL`：riscv 有 KASLR，但模块区随机化粒度仍可增强。
6. `ARCH_SUPPORTS_KEXEC_SIG` / `ARCH_SUPPORTS_KEXEC_IMAGE_VERIFY_SIG` / `ARCH_DEFAULT_KEXEC_IMAGE_VERIFY_SIG`：kexec 安全切换链路（签名与验签）能力位不完整。
7. `ARCH_SUPPORTS_KEXEC_HANDOVER`：二内核 handover 能力位缺失，影响 crashkernel/热升级路径。
8. `PTDUMP_STAGE2_DEBUGFS`：虚拟化 stage-2 页表调试可观测性弱。
9. `ARM64_LPA2` / `ARM64_FORCE_52BIT`：超大地址空间策略和页表扩展能力有差距。
10. `ARM64_TLB_RANGE`：缺少硬件范围失效接口，TLB shootdown 优化空间受限。
11. `ARM64_RAS_EXTN`：硬件级 RAS 能力差距影响高可靠场景。
12. `ARM64_SME`：矩阵扩展缺失，HPC/AI 方向上限受影响。

## 6. 适当扩展：非“真实缺失”项说明
- 平台/SoC（51项）与 CPU 勘误/缓解（65项）大多属于 Arm 厂商和微架构专属，不应机械视作 riscv 功能落后。
- 加密加速（12项）多数为“部分等价”：riscv 已有 `CRYPTO_AES_RISCV64`/`CRYPTO_GHASH_RISCV64`/`CRYPTO_SM3_RISCV64`/`CRYPTO_SM4_RISCV64`，但在 CCM/GCM/bitslice 等子模式或优化粒度仍有可补空间。
- AArch32 历史兼容项（如 `SWP_EMULATION`、`CP15_BARRIER_EMULATION`、`KUSER_HELPERS`）对 riscv 普遍不适用。
