# linux-arm-kernel 2025-2026 驱动与平台抽象 RISC-V 可移植性审计

## 1. 审计范围与方法

- **数据源**：`data/parsed/patches.jsonl` 与 `data/parsed/supplemental_patches.jsonl`，共扫描 **65,635** 条唯一补丁记录。
- **时间范围**：`2025-01-01T00:00:00Z` 至 `2026-07-10T23:59:59Z`。
- **主题范围**：通用驱动框架、PCI/PCIe、ACPI/EFI、固件、PM/genpd、DMA、SoC/平台抽象及可跨架构复用的通用 IP 驱动。
- **自动筛选**：按标题、正文、补丁标签和 touched paths 流式扫描全部记录；初始命中 21,814 条，按规范化标题和修订谱系合并为 9,888 条候选。另排除纯 DTS/板级数值变化 4,219 条、非目标范围 32,416 条、低分噪声 7,126 条。
- **人工核查**：逐项检查 67 条高价值代表邮件的正文、版本谱系、lore 链接和 touched paths，并将同一功能的修订或紧密配套补丁合并。
- **最终结果**：形成 **62 个独立潜在贡献点**。其中一部分是可直接被 RISC-V 共用的通用内核改动；一部分需要 RISC-V 平台驱动接入；另有一部分依赖特定硬件 IP、ACPI 表或固件 ABI。
- **排除原则**：不收录仅修改 ARM DTS 节点、时钟频率、中断号、寄存器地址、板级 pinctrl 或 regulator 数值的补丁。

### 优先级定义

- **P0**：通用框架已具备或改动天然跨架构，RISC-V 可直接启用、补测试或迁移现有驱动。
- **P1**：价值高，但需要具体 RISC-V SoC、固件、IOMMU/MSI、PCIe 控制器或电源拓扑配合。
- **P2**：长期平台能力或健壮性改进，当前缺少明确 RISC-V 硬件需求，适合跟踪和按需实现。

## 7. 建议优先推进的 RISC-V 贡献包

### A. 可立即推进的通用框架清理

1. **DMA non-coherent batching**：为 Zicbom/vendor CMO 实现批量 issue + 最终 fence，并对 dma-direct、dma-iommu、SWIOTLB 跑性能和一致性测试。
2. **PCI host-common 接入**：在 RISC-V DWC/PLDA host 中采用公共 link delay、ECAM、port parsing 和地址偏移 helper。
3. **驱动生命周期 API**：推广 `devm_alloc_workqueue()`、managed runtime PM、managed DMA channel/controller、clock bulk helper。
4. **fwnode 化**：优先接入 SCMI core、PCI MSI RID、PCS、reboot-mode 和 named-child/graph scoped helper。
5. **genpd 完整性**：补 `sync_state()`、domain hierarchy 和 `dev_pm_genpd_is_on()` 的 RISC-V provider/consumer 用例。

### B. 需要平台或固件配合的高价值项目

1. **RISC-V SCMI enablement**：先完成 Kconfig/命名去 ARM 化及 fwnode core，再选择 mailbox/PCC/SBI bridge transport。
2. **ACPI/AIA probe dependency**：验证通用 ACPI IRQ autodep 对 RINTC、APLIC、IMSIC 和 PCI MSI 的启动顺序。
3. **PCI endpoint 能力**：在具备 EPC 的 RISC-V SoC 上实现 platform-MSI doorbell、DOE 和 auxiliary DMA resource。
4. **CoVE DMA**：围绕 shared/decrypted allocation、no-bounce 可信设备与 SWIOTLB granule 建立完整威胁模型后再实现。
5. **RAS estatus**：定义 RISC-V firmware-first error provider，把异常上下文、memory_failure 与用户态 SIGBUS 语义接到通用 core。

## 8. 结论

- 本轮从全量邮件记录中得到 **62 个**经人工核查、合并修订后的潜在 RISC-V 贡献点。
- 最值得优先投入的是：**SCMI 架构无关化、DMA non-coherent 批量同步、PCI host-common/地址转换、ACPI IRQ probe dependency、genpd 层次与同步、fwnode 化以及通用 driver devres 生命周期 API**。
- ARM 邮件列表中的大量补丁实际修改的是 `drivers/`、`include/linux/`、`kernel/dma/` 等通用层；“由 ARM 平台提出”并不等于“只能用于 ARM”。报告已在每项中区分原始用例、通用子系统和 RISC-V 的实际接入位置。
- 硬件强相关条目只有在 RISC-V 平台采用相同 IP 或固件协议时才应直接复用；否则更适合作为接口和状态机设计参考，而不是逐行移植。
